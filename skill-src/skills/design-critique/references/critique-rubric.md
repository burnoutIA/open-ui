# Critique Rubric

## 1. Clarte

Questions :

- Que peut faire l'utilisateur en 3 secondes ?
- Quelle decision l'ecran aide-t-il a prendre ?
- Les actions primaires/secondaires sont-elles evidentes ?
- Les etats importants sont-ils visibles ?

Corrections typiques :

- renommer les actions ;
- reduire les elements concurrents ;
- rapprocher action et contexte ;
- rendre les etats visibles par structure, pas seulement par couleur.

## 2. Composition

Questions :

- Le layout a-t-il un centre de gravite ?
- Les colonnes ont-elles une raison produit ?
- Les blancs creent-ils respiration ou trous ?
- Les ruptures responsive cassent-elles le rythme ?

Corrections typiques :

- resserrer les zones pauvres ;
- donner une largeur stable aux elements fixes ;
- aligner les axes forts ;
- regrouper par decision utilisateur plutot que par type de composant.

## 3. Hierarchie visuelle

Questions :

- Le titre est-il proportionne a son role ?
- Les chiffres, statuts ou alerts utiles ressortent-ils ?
- Les boutons ont-ils une priorite claire ?
- La typographie guide-t-elle ou decore-t-elle ?

Corrections typiques :

- limiter les niveaux de titre ;
- renforcer un axe typographique ;
- deplacer les details hors de la zone primaire ;
- utiliser contraste, taille, poids et position de facon coherente.

## 4. Caractere

Questions :

- Peut-on reconnaitre le produit sans logo ?
- Y a-t-il une signature dans la composition, interaction, ton ou matiere ?
- Le style est-il choisi ou seulement genere ?

Corrections typiques :

- introduire un motif visuel fonctionnel ;
- choisir un modele d'interaction plus distinct ;
- utiliser des medias ou textures pertinents ;
- durcir une contrainte de gout.

## 5. Accessibilite et confiance

Questions :

- Les contrastes tiennent-ils ?
- Le focus clavier est-il visible ?
- Les labels et noms accessibles sont-ils explicites ?
- Les couleurs ne portent-elles pas seules l'information ?
- Les erreurs et etats d'attente sont-ils dignes et reparables ?

Corrections typiques :

- augmenter contraste et tailles ;
- ajouter libelles et descriptions utiles ;
- rendre les etats textuels ;
- verifier navigation clavier et ordre DOM.

## 6. Design-system potential

Questions :

- Quels composants seraient extraits ?
- Quels tokens seraient necessaires ?
- La direction cree-t-elle une dette ou un langage reusable ?
- Les exceptions sont-elles justifiees ?

Corrections typiques :

- identifier 3 a 7 primitives reutilisables ;
- transformer les choix recurrents en tokens ;
- isoler les moments expressifs ;
- documenter les interdits.
